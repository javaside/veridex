# Veridex 控制台视觉重构设计

## 目标

在不改变现有路由、API 契约和知识入库业务流程的前提下，重构 Veridex 登录页、全局应用框架、知识管理页面及尚未实现工作区的占位页面，使控制台具备企业产品应有的信息层级、可扫描性、完整状态反馈和响应式体验。

## 设计判断

Reading this as: 企业级知识管理控制台，面向知识管理员，进行视觉重构但保留现有路由与业务流程，倾向 Fluent UI 的克制 B2B 产品语言。

设计参数：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 3`
- `VISUAL_DENSITY: 6`

本项目是管理控制台，不采用落地页式巨型标题、营销 Hero、玻璃拟态、AI 紫色渐变或炫技滚动动画。设计重点是长时间工作的舒适度、数据状态清晰度、操作安全和键盘可达性。

## 设计系统选择

采用 Fluent UI 启发的企业产品语言，但不引入 `@fluentui/react-components`。当前页面规模小，现有实现使用 React 和原生 CSS；为减少依赖和迁移成本，本次建立轻量语义 CSS Token 和聚焦组件，而不是混用第三方组件系统。

这不是官方 Fluent UI 实现。借鉴范围仅包括：

- 克制的中性色层级
- 单一低饱和强调色
- 清晰的导航与页面标题结构
- 紧凑但可读的表单和列表密度
- 完整的 hover、focus、disabled、loading、empty 和 error 状态

## 视觉语言

### 色彩

页面锁定为浅色主题：

- 页面底色：冷灰白
- 主表面：近白色
- 次级表面：浅冷灰
- 主文字：深蓝灰
- 次级文字：中性蓝灰
- 唯一强调色：低饱和墨绿
- 成功、警告、失败和离线色仅用于真实语义状态

不使用外发光、霓虹、彩色渐变或纯黑纯白。所有文字、输入、按钮和状态标签满足 WCAG AA 对比度。

### 字体

使用系统 sans-serif 栈：`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC` 等，避免网络字体依赖和加载抖动。标题以字重和间距建立层级，不依赖过大字号。

### 形状

统一形状规则：

- 内容面板：12px
- 输入框：8px
- 按钮：8px
- 状态标签：6px
- 头像：圆形

阴影只用于需要提升层级的登录面板、弹出层和预览侧板；普通内容区优先使用边框和留白。

### 动效

动效只表达反馈和状态变化：

- 页面与面板轻微淡入
- 导航、按钮和列表项 hover 反馈
- 按钮按下时轻微位移
- 侧边预览面板进入与退出
- 骨架加载使用克制 shimmer

只动画 `transform` 和 `opacity`。`prefers-reduced-motion: reduce` 时禁用非必要动画。

## 全局应用框架

### 桌面布局

使用 240px 左侧文本导航和弹性主内容区：

1. 品牌区：Veridex 名称和本地开发环境标识
2. 导航区：员工问答、知识管理、质量评测、平台管理
3. 用户区：头像缩写、显示名、角色和退出操作

主内容区包含统一 PageHeader：

- 页面标题
- 一句功能说明
- 可选上下文操作

内容容器最大宽度约 1440px，避免超宽屏内容无限拉伸。

### 移动布局

小于 768px 时：

- 左侧栏改为顶部品牌栏和横向可滚动导航
- 页面内容严格单列
- 知识库列表位于工作区内容之前
- 表格型版本行改为堆叠布局
- 预览侧板改为全屏覆盖层

所有主要按钮保持至少 44px 可点击高度。

## 登录页

### 布局

桌面使用左右分栏：

- 左侧品牌说明：产品定位、当前可用能力和本地运行状态提示
- 右侧登录主体：紧凑表单和开发账号提示

不显示虚构客户、指标或图表。小屏幕隐藏品牌说明，只保留登录主体。

### 表单行为

- 标签始终位于输入框上方
- 用户名和密码保留浏览器自动填充属性
- 提交期间按钮显示“正在登录”并禁用重复提交
- 登录错误在表单内展示，使用 `role="alert"`
- 本地开发账号提示明确标注仅适用于本地环境
- 输入和按钮具有可见键盘焦点环

## 知识管理页

### 页面头部

PageHeader 显示：

- 标题“知识管理”
- 简短说明
- 知识库数量摘要
- 主要操作“新建知识库”

### 知识库列表

左侧知识库导航作为独立面板：

- 列表项显示名称和状态
- 当前项使用强调色边框和浅色背景
- 新建操作打开行内创建区域，不永久占用列表顶部
- 创建时显示忙碌状态，错误时保留输入并显示行内错误
- 初次加载使用匹配列表形状的骨架
- 空状态解释如何创建第一个知识库
- 加载失败显示错误和重试按钮

列表首次加载完成后，如果存在知识库且用户尚未选择，默认选中第一项。

### 知识库工作区

选中知识库后显示：

- 知识库名称和状态
- 文档数量和 Release 数量摘要
- 上传文档入口
- 文档与版本区域
- 索引发布区域

未选择知识库时显示结构化空状态，而不是一行灰色文字。

### 上传区

上传区为清晰文件选择面板：

- 文件输入保留原生可访问行为
- 显示支持 PDF、DOCX、TXT、Markdown，最大 50 MB
- 选择文件后显示文件名和大小
- 上传期间禁用提交和文件重选
- 上传成功显示可感知反馈并刷新数据
- 上传失败显示上下文错误，不静默吞掉异常

本次不实现拖拽上传，避免增加不必要的交互和测试范围。

### 文档和版本

文档列表使用可展开行：

- 主行显示文件名、类型、大小或上传时间（仅使用 API 已提供字段）
- 展开后展示版本号、处理状态、Chunk 数量和可用操作
- 状态标签使用中文语义和统一颜色
- `READY` 版本提供预览操作
- 无文档时显示上传引导
- 版本加载失败显示该文档范围内的重试状态

不伪造 API 未提供的时间、大小或处理耗时。

### 解析预览

预览从可点击 `<pre>` 改为语义侧边面板：

- 标题、文档版本信息和关闭按钮
- 解析文本使用可滚动正文区域
- Escape 和关闭按钮均可退出
- 打开后管理焦点，关闭后将焦点返回触发按钮
- 移动端占满视口

### 索引发布

Release 列表独立于文档列表：

- 显示版本、状态和索引名
- 索引名使用等宽字体并允许复制式选择
- 只在状态允许时启用对应操作
- 回滚和离线为次级操作
- 删除为危险操作
- 删除前使用浏览器原生确认对话框，避免为单一确认场景引入新的 Modal 组件系统
- 操作中禁用当前行按钮
- API 失败显示行内错误和重试可能性

## 尚未实现的工作区

员工问答、质量评测和平台管理使用统一 `ComingSoonPage`：

- 保留真实页面标题和导航
- 显示所属路线图阶段
- 简要列出计划能力，不虚构业务数据
- 提供返回知识管理的明确链接

三个页面共用组件，但文案与阶段不同。

## 状态模型与错误处理

每个远程数据区域独立维护：

```text
idle -> loading -> success | empty | error
```

要求：

- 不再使用 `.catch(() => {})` 静默吞错
- 错误信息位于发生错误的区域内
- 可恢复读取错误提供“重试”按钮
- 写操作错误保留用户当前上下文
- 所有异步按钮防止重复提交
- 状态文本通过 `aria-live` 或 `role="status"` 暴露给辅助技术

## 组件边界

计划建立或重构以下组件：

- `AppShell`：全局导航、用户区和主内容框架
- `PageHeader`：页面标题、说明和操作
- `ComingSoonPage`：未实现工作区占位
- `LoginPage`：品牌区和登录表单
- `KnowledgePage`：知识库选择和工作区编排
- `KnowledgeBaseList`：知识库加载、选择、创建和错误状态
- `UploadForm`：文件选择、上传和反馈
- `VersionList`：文档与版本加载、展开和预览入口
- `ReleaseList`：Release 状态和操作
- `PreviewDrawer`：解析文本侧板
- `StatusBadge`：统一状态映射

不引入全局状态库；现有数据规模使用局部 React state 即可。

## API 与功能保持

保持以下内容不变：

- 路由：`/login`、`/workbench`、`/knowledge`、`/evaluation`、`/admin`
- 登录、知识库、上传、文档、版本、预览和 Release API 地址
- Session 认证方式
- 上传格式和大小限制
- Release 回滚、离线和删除语义

允许扩展 `knowledgeApi` 的错误包装和返回类型，但不修改后端契约。

## 依赖策略

当前 `web/package.json` 没有图标库。若实施需要图标，统一安装 `@phosphor-icons/react`，禁止手写 SVG 和混用图标族。不引入 Tailwind、Motion、Fluent UI 或其他组件库；本次动效由 CSS 实现。

## 测试与验证

### 组件测试

扩展 Vitest + Testing Library 覆盖：

- 登录页字段、忙碌态和错误态
- 已登录 AppShell 导航与用户信息
- 未实现页面的统一占位内容
- 知识库加载、默认选择、空状态、错误重试和创建
- 上传成功、失败和忙碌状态
- 文档展开、版本状态和预览侧板
- Release 状态操作、危险确认和错误反馈

测试用户可观察行为，不断言内部 state 或纯 CSS 实现。

### 浏览器验证

使用 Chrome DevTools 检查：

- 1440x900 桌面布局
- 390x844 移动布局
- 登录、知识管理、空状态和预览侧板
- 键盘焦点顺序和 Escape 关闭
- 控制台错误和失败网络请求
- Lighthouse Accessibility、Best Practices 和 SEO
- `prefers-reduced-motion` 下无非必要动画

### 构建门禁

运行：

```bash
npm --prefix web test
npm --prefix web run lint
npm --prefix web run build
```

本次修改前端代码，必须执行前端测试、Lint 和构建；不需要运行与前端无关的完整后端测试套件。

## Pre-Flight 约束

- 一个浅色主题，不做页面内主题翻转
- 一个墨绿强调色
- 统一圆角系统
- 无 em dash 字符
- 无 AI 紫色渐变、玻璃拟态、外发光和三等分卡片
- 无虚构指标、客户、图表或版本标签
- 无装饰性状态点
- 所有表单标签、错误、焦点和按钮对比度满足 WCAG AA
- 桌面导航单行，移动布局明确
- 所有非必要动画支持 reduced motion
- 加载、空、错误、成功和禁用状态完整

# v0.1.0 — 首个开源发布

> 发布日期：2026-08-21
> 版本类型：首个发布（功能全景 + 安全声明）

## 这是什么

Veridex 是面向**企业私有化部署**的 RAG（检索增强生成）平台。它以「知识库 → 检索 → 带引用回答」为主线，覆盖从文档入库、索引发布、授权问答，到质量评测与运营反馈闭环的完整链路。

本轮发布是项目首次开源，已实现 Phase 1 至 Phase 5-e 的主体能力。源码以 [Apache License 2.0](../../LICENSE) 授权，附带 backend/web 双容器镜像、Compose 应用栈、原生 Helm chart 与受限网络离线交付。

## 功能全景

### 身份与授权

- 本地用户、Session 登录与 `PLATFORM_ADMIN` / `KNOWLEDGE_ADMIN` / `EMPLOYEE` 角色
- 知识库创建及 VIEW / MANAGE 授权模型
- 平台级 scoped API key（作用域授权、吊销、使用时间记录）

### 知识入库

- PDF / DOCX / TXT / Markdown 上传（单文件最大 50 MB），Apache Tika 解析
- 结构优先分块（Markdown 标题驱动 + 超长硬切 + overlap）
- PostgreSQL Transactional Outbox + RabbitMQ 异步入库，重复消息幂等、失败版本隔离
- MinIO 原始文件与解析产物存储
- OpenSearch 全文（BM25）+ 向量（knn_vector）双字段写入
- 不可变 IndexRelease：发布、设为当前、离线、删除；发布失败不影响旧快照

### RAG 查询

- 授权知识范围（多知识库交集）上的混合检索：BM25 + 向量 + RRF 融合 + 上下文组装
- 有限多轮会话、SSE 流式回答、`[n]` 引用校验与原文预览
- 依据不足时明确拒答（`ACCESS_RESTRICTED` 统一文案）
- 多 provider：`deepseek`（默认，`deepseek-v4-flash`）/ `ollama`（对话）、`ollama`（向量）、`deterministic`（测试占位）

### 质量评测与运营闭环

- 版本化评测集（`DatasetVersion` 不可变快照 + 冻结用例，ANSWER / REFUSE 期望行为）
- 不可变 RAG 配置版本（chunking / retrieval / generation / prompt / model 五维 + 「当前生效」标记）
- 同步评测运行与自动指标（Recall@K、MRR、NDCG、citation hit、refusal match、latency）
- 两评测运行逐指标对比与回归门禁（相对退化阈值）
- 点赞/点踩反馈落库与坏例转评测集闭环

### 企业就绪（Phase 5）

- 可观测性：Prometheus / Grafana / OTel Collector / Tempo 本地栈；受控 Trace Body（AES-256-GCM 加密、审计读取 API、保留策略）
- 安全加固：出站访问策略（防 SSRF）、解析沙箱、上传预算、对象授权隔离、提示注入隔离、Actuator 管理端口隔离
- 容器化部署：非 root backend/web 镜像、Compose 完整应用栈、原生 Helm chart、NetworkPolicy、离线交付包
- 备份恢复：PG 逻辑备份 + MinIO 对象导出 + SHA-256 清单；源重建恢复（实测 RTO=21s）

## 快速开始

```bash
# 1. 启动基础设施
docker compose -f deploy/compose/compose.yml up -d

# 2. 启动后端
./mvnw -pl backend spring-boot:run

# 3. 启动前端
npm --prefix web ci
npm --prefix web run dev
```

访问 `http://localhost:5173`，使用 `admin` / `veridex` 登录。完整步骤见 [README](../../README.md#快速启动)。

## 已知限制

- `deterministic` embedding（128 维确定性哈希）无语义；真实语义需 `VERIDEX_EMBEDDING_PROVIDER=ollama`（1024 维）。
- 评测为「仅自动指标」的同步运行；judge-model 自动评判与人工评审尚未实现。
- 回归门禁阈值（相对退化 10%）为硬编码默认值，尚未配置化。
- 配置 Profile 的 `chatModel` / `embeddingModel` 字段仅作标识记录，未接入运行时模型路由（当前单一模型装配）。
- 改 `chunking` 后仅对之后新入库的文档生效，存量文档需重新入库才会重切。
- 失败消息进入 DLQ；自动重试、退避与 Outbox 定时恢复仍待增强。

## 安全声明（请先读）

Veridex 面向私有化部署，安全边界是设计的一部分，但**不是银弹**。发布前请务必阅读 [SECURITY.md](../../SECURITY.md) 的「已知且被接受的风险」与「安全最佳实践」，尤其是：

- **默认开发凭据**：`admin`/`kadmin`/`employee` 与 RabbitMQ/MinIO/PostgreSQL 默认密码只用于本地开发，**禁止用于共享测试或生产环境**。
- **本地开发默认关闭 OpenSearch 安全插件**：生产部署必须启用并配置凭据。
- **API 限流为每副本语义**：跨副本全局限额需自行引入共享限流存储。
- **真实模型 API key 只经环境变量或 Secret 注入**，不要提交到仓库。
